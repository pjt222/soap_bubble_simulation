# Project Audit — 2026-10-09

Workflow-based audit of `main` at `b4ecc02`, plus the uncommitted working tree (`src/render/branched_flow.rs` default
changes and a `CLAUDE.md` section). Scope: mathematical/physical correctness, simulation speed-ups,
parallelisation, GPU optimisation, and the 2026 Rust GPU / CUDA landscape.

## Method

- **Workflow `wf_30e602b2-7fc`**: 7 parallel auditors (optics, drainage, branched flow, geometry/foam, CPU perf,
  GPU perf, SOTA research), then 2 read-only adversarial verifiers. 87 findings in total.
- **Adversarial verification**: every critical/high finding and every medium math/physics finding — 43 in total —
  was re-checked against the code by a verifier that tried to refute it. Results: 34 confirmed, 9 partially
  confirmed (severity or detail corrected), 0 refuted. The remaining 44 findings (low/info, and medium findings
  that are not math) were **not** adversarially verified; the appendix labels them `unverified`.
- **What the verifier could and could not check**: the verifier agent was read-only (Read/Grep/Glob) and could not execute anything. It
  re-read the code and re-derived the math by hand. The numeric replica results quoted below were run by the
  *finders* only: polar blow-up within ~25 frames, 1.67 mm/frame foam jitter, ~170 scatterers per step, ΔE 27–97,
  57% deposit truncation, 97–99% pinned steps. The verifier checked them by reading, not by re-running. "0 refuted" should be
  read in that light.
- **Independent re-checks by the lead session** (not relying on the agents): Airy phase sign (numeric),
  GPU drainage `dt` path, `thickness_scale` usage, patch-mesh longitude convention, drainage default state.
- **Evidence tags**: `re-derived` = derivation written out, usually with a numeric replica in Python;
  `measured` = actually run on this machine; `estimated` = reasoning only. **No GPU timing in this report comes from
  hardware.** The dev machine renders via a CPU rasteriser (see §5). Every speed-up figure is
  `[estimated, requires measurement]`.
- Full per-finding claims, derivations, code quotes, recommendations and verifier reasoning are in
  `docs/audit-2026-10-09-findings.json` (the workflow's return value, verbatim). The numeric replica scripts
  (WGSL-kernel ports, CIE checks) are preserved as run in `docs/audit-2026-10-09-evidence/`; the scratchpad paths
  cited in the JSON map onto that directory (see its README).

## 2. Critical and high findings (all adversarially verified)

### 2.1 Thin-film colour is inverted — CRITICAL (re-derived ×3 auditors + lead re-check)

`interference_lut.rs:68`, `shaders/bubble.wgsl:464`, `shaders/bubble_instanced.wgsl:208` (and `+λ/2` in
`physics/interference.rs:248`) compute `phase = 2π·OPD/λ + π` and feed it to the Airy reflectance
`F sin²(φ/2)/(1+F sin²(φ/2))`. For a free-standing film (air|film|air), Airy already contains the half-wave flip
through `r21 = −r12`, so the extra π turns `sin²` into `cos²`: every fringe is inverted.

Lead check (n = 1.33, λ = 532 nm, exact complex-amplitude slab reflectance vs code):

| d (nm) | exact | code (+π) | without +π |
|---|---|---|---|
| 0 | 0.00000 | 0.07711 | 0.00000 |
| 100 | 0.07711 | 0.00000 | 0.07711 |
| 200 | 0.00000 | 0.07711 | 0.00000 |

The 30 nm hard black cutoff (`bubble.wgsl:517`) hides the d→0 symptom. Visible effect: films from 30 to ~100 nm
render bright where they should be dark, and every thicker film shows the complementary colour sequence. The optics
auditor measured ΔE76 = 27–97 over 30–800 nm against a 1 nm CIE 1931 × D65 reference. `git log -S` shows the
shader's `wavelength + pi` arriving in `4fef328` (2026-01-21, which per the optics auditor replaced a correct two-beam
`(1+cos φ)/2` form with Airy). It was carried into the LUT in `21747d7`. The existing tests check only value ranges. **Fix:** drop the `+π` / `+λ/2`, regenerate the LUT, and add a unit test asserting `R(0)=0` and
`R(λ/4n)=max`. Golden images in `tests/golden` must be regenerated afterwards.

### 2.2 Drainage solvers (both off by default, `pipeline.rs:801,813`)

- **GPU drainage is a no-op — HIGH.** `GPUDrainageSimulator::step` (`gpu_drainage.rs:355`) computes `step_dt` but
  only adds it to `current_time` (`:376`). `set_dt` (`:391`) has zero callers, so the shader always integrates with
  the default `dt = 0.001` s (`:49`). At h = 500 nm the per-step change is ≈0.007 ulp in f32, and a uniform start has zero
  Laplacian, so the buffer stays exactly uniform. Consequence: branched-flow GRIN bending and caustics read a flat
  field. The `time_scale` slider changes only the displayed clock, which runs ~167× fast. (Lead-confirmed in code.)
- **CPU drainage blows up when enabled — HIGH.** `drainage.rs:380`: one forward-Euler step per frame with
  `dt = frame_dt × 100` ≈ 1.67 s at 60 fps. The explicit φ-diffusion limit at the first ring off the pole is ≈0.115 s,
  so the scheme is ~14× over it. Numpy and Rust replicas blow up near both poles within ~25 frames.
- **PDE form and units — MEDIUM (downgraded from high).** The gravity term `−ρ g h³/(3η)·sinθ` is a flux (m²/s)
  used as a rate. It is a mass sink everywhere and is symmetric about the equator, so the bottom never thickens. The
  conservative lubrication form is `∂h/∂t = −(1/R sinθ) ∂_θ(sinθ · ρ g h³ sinθ /(3η))`.
- **"TFE ratio 0.85 (Monier 2025)" — HIGH.** `drainage.rs:457` applies it as unbounded exponential decay
  `h *= 1 − 0.075·dt`, which goes negative for dt > 13.3 s. Monier reports a bounded *ratio*, not a decay rate.

### 2.3 Branched flow

- **GRIN term is dead — HIGH (lead-confirmed).** `thickness_scale` (1e6, `branched_flow.rs:128`) is declared in
  `branched_flow_compute.wgsl:38` and never read. Gradients are taken on metre-valued thickness (~5e-7), so deflection
  over a full ray is ~2e-4°. All visible branching comes from the scatterers, and the "GRIN bending" slider effectively
  scales the particle force. `caustics_compute.wgsl:96` has the same unit bug and outputs a constant 2.0 (medium).
- **Patch view shows no branched flow — HIGH (lead-confirmed).** `SpherePatch` (`geometry.rs:411`) uses
  `phi = 2π·u` (u = 0.5 → −x). Both shaders use `u = (atan2(z,x)+π)/2π` (u = 0.5 → +x), half a turn apart. Full-sphere
  mode is unaffected.
- **Hidden behind that: the spawn mapping — MEDIUM.** `branched_flow_compute.wgsl:467`: the spawn offset is a chord
  projection, not a gnomonic one, and the default patch centre lies on the entry point's gnomonic horizon. Once the
  180° bug is fixed, only a thin strip of the patch would light up.
- **Scatterer drift is biased — HIGH (upgraded).** `branched_flow.rs:629`: the "Brownian" perturbation is a
  sign-preserving `fract()` hash of `film_time` with mean −0.0005 UV/frame. Scatterers pile into the (min u, min v)
  corner in ~10 s at 60 fps (or the pole/seam in full-sphere mode), emptying the region the beam crosses.
- **Temporal accumulation adds no samples — MEDIUM.** Ray seeds depend only on `ray_idx`
  (`branched_flow_compute.wgsl:439`), so the 0.85 fade gives 6.7× brightness of the *same* paths, not more paths.
  `hash21` also yields ~26% exact duplicate seeds at 65 536 rays (f32 ulp collapse). This directly undercuts the
  uncommitted change; see §6.
- **Adaptive step pinned at the 0.3 floor in 97–99% of steps — MEDIUM.** `branched_flow_compute.wgsl:515`. The
  uncommitted comment "adaptive stepping (0.3–3x) extends effective range" is false: stepping cuts range 3.3×.
- **Fixed-point deposits lose 53–62% of energy — MEDIUM.** The ×64 u32 encode truncates small per-step deposits.
- **Correct:** zero-force rays follow great circles (error 1.9e-15). Kick + renormalise gives dT/ds = k·F⊥ to first
  order. Frame handedness, ×64/÷64 encode/decode, u32 headroom and the prefix-sum spatial hash all check out.

### 2.4 Foam

- **Foam integrator is clamp-driven — HIGH.** `foam_dynamics.rs:186`: explicit Stokes drag with water viscosity and
  film-only mass (19–37× too little inertia) is unstable at frame dt. Bubbles jitter 1.67 mm/frame at the 0.1 m/s
  velocity clamp indefinitely.
- MEDIUM: Plateau's laws are claimed but not enforced (contact equilibrium gives ~36/162° angles); buoyancy omits the
  enclosed gas, so net gravity clamps to 0 for R > 1.25 mm; `wall.wgsl:187` renders the Airy *transmission* term as
  reflected colour; size distributions are clamped rather than truncated (up to 64% of radii pile on the bound).
- LOW: shared-wall curvature radius is half the physical value (`foam.rs:125`) and bulges into the smaller bubble.

### 2.5 Crash-class bugs (wgpu validation panics)

- **MSAA change panics — HIGH.** `pipeline.rs:1219` `set_msaa_samples` rebuilds only the bubble pipeline. The
  instanced, wall and caustic pipelines keep 4× and fail validation. Needs non-default toggles (MSAA change + foam or
  caustics).
- **GpuProfiler race — HIGH.** `gpu_timing.rs:157` copies into the readback buffer every frame even while its
  `map_async` is pending (`BufferStillMapped` → default handler panics). It also resolves all 16 query slots although
  ≤4 are written. Latent on lavapipe, expected to fire intermittently on real GPUs. This is a prerequisite for any
  hardware benchmarking. `wgpu-profiler` implements the ring-buffer pattern correctly.

### 2.6 Optics, medium

- The interference LUT is stored as linear `Rgba8Unorm` with values ≤0.04, which leaves ~9–10 code values on the
  normal-incidence row and causes contouring. Use `Rgba16Float` (128 KiB).
- The CIE Gaussian fit drops Wyman 2013's asymmetric σ and applies no illuminant (flat spectrum renders orange
  (1, 0.76, 0.43)). The 7-sample 50 nm spectral integration aliases (ΔE 6.5 at 500 nm, 19–31 above ~1.1 µm).
- **The procedural drainage gradient is upside down** (`bubble.wgsl:208`, `bubble_instanced.wgsl:327`):
  `(1 − normal.y)` makes the film thinnest at the bottom, with +Y up. The comment and README say the opposite.
- Correct: Snell with cos θ_t everywhere; full s/p Fresnel (not Schlick); Airy algebra identical across CPU, GPU and
  LUT apart from the phase; sRGB encode applied exactly once; standard D65 XYZ→sRGB matrix.

## 3. Performance and parallelisation (all figures `[estimated, requires measurement]` unless noted)

**CPU side is not the bottleneck.** A min-of-N timed rustc replica (measured, on a loaded 8-core machine) puts
scatterer perturb + sort + prefix-sum at 17 µs for n = 400 (94 µs for n = 2048). Per-frame bind-group creation and
the O(n²) foam loop (capped at 30 bubbles) are negligible against 16.7 ms. **No rayon work is justified** until CPU
drainage is sub-stepped correctly: ~15 sub-steps/frame ≈ 6 ms single-threaded [estimated]. At that point
`par_chunks` over θ rows becomes worthwhile, or better, an implicit φ solve.

Ranked GPU speed-ups on a real discrete GPU:

1. **Precompute a per-frame force-field grid** (GRIN gradient + scatterer forces → one `vec2` texture). Today each
   ray-step visits ~163–170 scatterers in patch mode (the docs say "~10–30"). Expected ≈10–25× less per-step work.
   Touches the propagation loop body; see §5 on the "GPU freeze" note.
2. **Turning-angle step control** instead of the pinned 0.3× clamp: ≈2.6× fewer steps for the same path length.
3. **Scale `num_rays` by adapter type.** 8 192 rays = 128 workgroups ≈ 12% occupancy on an RTX 3070 Ti Laptop
   (46 SMs). The 32K→8K cut was tuned for llvmpipe, where it does save ~4×; on hardware it mostly removes samples.
4. Fix or remove dead work: the GRIN loads on a frozen field, and 10 drainage passes per frame that change nothing.
5. Foam instanced shader: use the LUT instead of the inline 7-wavelength spectrum per fragment (matters mainly on
   CPU rasterisers).
6. Atomics and subgroups last (≈0.15 ms). **#36 is not viable as written** (random scatter defeats workgroup
   privatisation). **#37 is the wrong lever**: keep `@workgroup_size(64)`; larger groups idle SMs at 8K rays.

Other: recording mode does `poll(Wait)` and joins the previous PNG encode per frame (`frame_exporter.rs:169`). Use 2–3
staging buffers plus a persistent encoder thread with `CompressionType::Fast`. The ping-pong accessor returns the last
sub-step's *input* (one sub-step stale), so the per-frame bind-group rebuild is redundant; two cached bind groups
would do.

## 4. Rust GPU / CUDA landscape (Oct 2026, sources fetched)

- **Do not move compute to CUDA.** NVIDIA's WSL guide (v13.4, Sep 2026) states OpenGL–CUDA interop is unsupported on
  WSL, so every frame would round-trip through the host. The workload is small, and the Rust CUDA stacks call
  themselves early-stage: Rust-CUDA rebooted in 2025 with its last tag in 2022; NVIDIA `cuda-rust` / cuda-oxide 0.2
  is "early-stage research"; rust-gpu v0.10.0 is "not yet production-ready".
- **CubeCL** is the only Rust-kernel option that can share the renderer's wgpu device (zero-copy). It needs wgpu 30.
  Keep it on the watch list.
- **wgpu 24 → 30** (latest 30.0.1, 2026-08-22; egui-wgpu 0.36.2 requires `^30`) is optional maintenance and does
  **not** fix #38. Subgroups already exist in wgpu 24. Estimated 0.5–1.5 days as a single PR.
- **Method SOTA worth adopting.** Thin film: Huang et al. 2020's reduced model fits the existing lat-long grid
  (their CUDA+AmgX version: 1024×2048, 1.1 s/step on a GTX 1080). Polar stiffness: implicit φ diffusion per latitude
  ring via periodic tridiagonal / parallel cyclic reduction (Zhang–Cohen–Owens 2010); a cube-sphere grid is the
  heavier alternative. Branched flow: keep the ray model (Patsyk 2022 PRX: the main branches are ray caustics), but
  bend with ∇ln n_eff(d) from the slab-waveguide dispersion, not ∇d. Iridescence: Belcour & Barla 2017 (spectral
  antialiasing of the Airy term) is the reference point beyond a fixed 7-sample LUT.

## 6. The uncommitted working-tree change

The new `BranchedFlowParams` defaults (8 192 rays, 200 steps, 400 scatterers) rest on two premises, and both are
false: the fade does not accumulate new samples (frame-invariant seeds), and adaptive stepping does not extend range
(pinned at 0.3×). On llvmpipe the cut does buy ~4× speed. On a hardware GPU it mostly discards samples at ~12% occupancy.
Recommendation: before committing, either fix the seeds (PCG hash of `ray_idx ^ frame·0x9E3779B9` — changes initial
conditions only, which is safe per `CLAUDE.md`) or keep the defaults but correct the comments. Pick `num_rays` per
adapter type.
